This page does not save anything by itself. Command Center's dashboards are static files with no database, so there is nothing here for this tool to write to directly. It parses a CSV, lets you map its columns to the real schema, runs the exact same checks as node public/garage/data/validate.js, and then gives you a JSON file to download and use to replace public/garage/data/listings.json by hand. Nothing is invented: a blank cell stays null, never a guess, and a row with no id column gets one generated with the exact same slug rule the "Quick log a new listing" tool on the main page already uses. soldOn and listingUrls always come out empty, the same rule that tool follows: a freshly imported row hasn't sold or been posted anywhere yet.
This never posts or publishes anything. There is no live connection to eBay, Vinted, Poshmark, or Depop, so importing a batch can't actually list anything on your behalf. It only ever builds a downloadable file of items Jack already has real photos/drafts for, the same read-only-reference scope as the rest of this hub. A blank status column defaults to "ready-to-post", not "live", since a bulk-imported row (e.g. the 48-item Depop drafts backlog) isn't actually published anywhere until it really is.

2. Paste or choose a CSV file

The first row must be a header row. Column names don't need to match the schema exactly, the next step lets you map each one, and any column you don't map is ignored. One row per listing. Platforms can hold more than one platform in a single cell, separated by a comma, semicolon, pipe, or slash, e.g. ebay, poshmark, depop.

3. Map columns

Guessed automatically from the header names where possible. Check each one, especially platforms and status: a typo'd platform name (anything not actually eBay, Vinted, Poshmark, or Depop) will show up as a real validation error below rather than being silently dropped.
