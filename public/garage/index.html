How to log a real update (until a backend is wired in)

Edit the JSON files by hand under public/garage/data/, then run node public/garage/data/validate.js. Leave any field you don't have a real answer for as null, do not fill it in with a guess.

listings.jsonOne object per listed item in the listings array.
idUnique slug, e.g. "black-boots"
titleItem name as it appears in the listing
priceUSD asking price, a number or null
costBasisUSD cost of actually acquiring this item (what it was paid for), a non-negative number or null. Drives real profit figures separate from the fee-only payout estimates below, leave null until you have the real number, never guess it.
platformsArray of any of: ebay, vinted, poshmark, depop
soldOnArray, subset of platforms, marking which of them the item has actually sold on so it can be manually delisted from the rest. Leave [] until a real sale happens on one platform while the item is still live on others.
listingUrlsOptional object keyed by platform (each key a subset of platforms), value the real live listing URL as a string once it's been copied over, or null until logged. Powers a direct "View listing" link per platform in the item detail view, never invent a URL, leave it null rather than guess.
statusOne of: draft, ready-to-post, live, sold
datePublishedISO date (YYYY-MM-DD) or null if not tracked yet. Also drives the "Relist reminders" section below, log the real date an item first went live to get relist guidance for it.
notesFree text, or null
pipeline.jsonOne object per pipeline stage in the stages array, each with a stage, integer count, and optional note.
activity.jsonOne object per logged event in the events array: real bug fixes, photo audits, and other quality checks. Requires id, title, and type (bug-fix, photo-audit, or other).
sales.jsonOne object per real completed sale in the sales array. Log a sale here and add that platform to the item's soldOn array in listings.json, both matter: this is the sale history, soldOn is what still needs delisting elsewhere.
idUnique slug for the sale, e.g. "black-boots-ebay-2026-09"
listingIdThe id of the matching entry in listings.json, or null if that listing was fully sold through and removed
titleItem name, kept here too so sale history survives the listing being removed later
platformWhich platform it actually sold on: ebay, vinted, poshmark, or depop
salePriceUSD price it actually sold for, a non-negative number (can differ from the asking price on an accepted offer)
askingPriceUSD asking price at time of sale, or null if not tracked
costBasisUSD cost of acquiring the sold item, a non-negative number or null. Usually copied over from the matching listing's own costBasis at the time it sold; drives the real profit column in the sales log, stays null until known.
shippingCostUSD actually spent shipping this sale out (postage, box, mailer), a non-negative number or null. Only real on a platform where the seller pays for shipping rather than the buyer covering it separately (see the shipping note on the price calculator above); leave null until the real receipt is known, it also feeds the profit column in the sales log.
saleDateISO date (YYYY-MM-DD) or null if not tracked yet

Title fit by platform

Real published title-length caps per platform, sourced from each platform's own seller/help documentation as of September 2026. eBay silently truncates a title past its cap at publish, Vinted and Poshmark reject it outright, this is the same class of silent-failure problem as the eBay return-policy bug logged above, catching it before publish is the point. This reads the real title already logged per item, it isn't a separate field to maintain.
Title & photo specs by platform
eBayTitle: 80-character hard cap. Photos: up to 24 free, 500px minimum on the longest side (1600px+ enables zoom), no watermarks/text/borders, must be the actual item (no stock photos on used goods).
VintedTitle: 70-character hard cap. Photos: square-cropped thumbnail in feed/search, a non-square upload gets center-cropped.
PoshmarkTitle: 80-character hard cap. Photos: up to 16, square-cropped cover thumbnail.
DepopTitle: no published hard cap, but mobile search visibly truncates around 50 characters, so front-load brand and item type. Photos: 1280px recommended, square cover crop.

Relist reminders

Platform-aware guidance on when to refresh a live listing that hasn't sold. eBay, Vinted, and Depop's search all favor listing recency, common reseller practice is to relist or renew after about 30 days without a sale. Poshmark is the exception: its Excessive Listing Removal Policy blocks relisting the same item again before day 60, doing it earlier risks the listing getting pulled instead of refreshed. This needs a real datePublished logged per item to compute anything, it stays honestly blank until then, no guessed dates.

Est. net payout by platform

Estimates only, not a live account connection. Computed from each platform's standard published 2026 seller fee schedule against the asking price above. Actual payout can differ by item category, seller level, active promotions, or a fee schedule change since this was last checked. The best tag marks the platform that nets the most for that item among the ones it's actually listed on, worth knowing if a buyer offer comes in on more than one platform at once.
Fee formulas used
eBay13.6% final value fee (standard rate, most categories) + $0.30 per-order fee, $0.40 on orders over $10
VintedNo seller fees, buyer pays a separate buyer protection fee
PoshmarkFlat $2.95 on sales under $15, otherwise 20% commission
Depop3.3% + $0.45 Depop Payments processing fee, no seller commission (US/UK)

Price a new item

Quick what-if calculator, not tied to any logged listing. Type an asking price to see the estimated net payout on each platform before a draft even exists. Uses the same fee formulas as the payout table above, toggle a platform off if this item wouldn't go there. Add what the item actually cost to get it (thrifted price, wholesale cost, etc.) and what it actually costs to ship (postage, box, mailer) to see real estimated profit alongside the fee-only payout. Shipping only matters on a platform where the seller pays for it out of the sale, most resellers offer "free shipping" on eBay and Depop and eat that cost, while Poshmark and Vinted both charge the buyer a separate shipping fee on top of the price, so leave shipping cost out for those if the buyer is really covering it. Both fields are optional and purely a scratch calculation, neither gets saved anywhere.

Sales log

Every real completed sale, one row per platform a sale happened on. Nothing here is estimated, this only shows what's actually been hand-logged in sales.json after a real sale. Logging a sale here is separate from marking that platform in the item's soldOn array above, a real sale needs both done, one to log the sale itself and one to flag that item for delisting elsewhere. Profit is only shown once a real costBasis or shippingCost is logged for that sale, it stays honestly blank otherwise rather than assuming either one is $0, and only ever subtracts the one(s) that are actually logged.

Tax / 1099-K threshold tracker

Not tax advice. As of the 2026 tax year, the federal Form 1099-K reporting threshold is back to more than $20,000 in gross payments AND more than 200 transactions, per platform, restored permanently by the One Big Beautiful Bill Act (July 2025). A platform only has to send a 1099-K once both numbers are crossed, but every dollar of real profit is taxable income regardless of whether a form gets issued. This reads only real rows from sales.json for the current calendar year, it does not estimate or project future sales.
