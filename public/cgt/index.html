How to log a real card (until a backend is wired in)

Edit public/cgt/data/cards.json by hand and add an object to the cards array. Leave any field you do not have a real answer for as null, do not fill it in with a guess. If the real data already exists as a CSV export from the tracker file, the Import CSV page will map its columns to this schema, validate it, and hand back a ready-to-save cards.json instead of retyping everything by hand.

Run node public/cgt/data/validate.js after every edit. It catches duplicate ids, a missing or unlabeled valuationBasis on a priced card, a comp-estimate with no compNote explaining what it is based on, and bad dates. It also warns (not an error, since owning two real copies of the same card and grade is a real thing) when the same card name, year, grading company, and grade shows up on more than one row, in case a row got copy-pasted and only the id was changed.

A priced card gets a stale badge once its datePriced is more than 180 days old. That is not an error, card market prices just drift over months, and it is a nudge to re-check the price next time you are in this hub, not something to fix immediately.

If gradingCompany is PSA, BGS, SGC, CGC, or KSA, the card's detail view links out to that company's real cert-verification tool (PSA and BGS link straight to the cert when certNumber is filled in, the others open the lookup tool for you to enter it by hand since they don't expose a direct-link URL). HGA has no public lookup tool as of this writing, so no link is shown for it.

idUnique slug, e.g. "2021-topps-chrome-julio-rodriguez-psa10"
cardNameFull card description, e.g. "2021 Topps Chrome Julio Rodriguez RC"
sportOne of: hockey, baseball, football
gradingCompanyPSA, BGS, SGC, CGC, HGA, or KSA
gradeThe grade as shown on the slab label, e.g. "10" or "9.5"
certNumberThe grading company's cert / serial number, for looking the card back up later
storageLocationOptional plain-text note on where the physical card actually is, e.g. "Home safe" or "Safe deposit box #4". Not required, but the insurance/appraisal print view shows it per card since a real appraisal document is far more useful when it also says where each item is kept.
estimatedValueUSD number. Leave null until it has actually been researched, never estimate in bulk.
valuationBasisRequired whenever estimatedValue is set. "recent-sale" if a real comparable sale at this exact grade was found, "comp-estimate" if none exists and the number is inferred from other grades or similar cards.
compNoteRequired when valuationBasis is comp-estimate. Plain-language note on what the estimate is based on, e.g. "No PSA10 sales found, based on 3 PSA9 sales + typical grade premium"
sourceNoteWhere the price came from, e.g. "eBay sold listings, 3 comps, Aug 2026"
costBasisUSD number, what was actually paid for the card. Optional and independent of estimatedValue: log it when known, leave null when not. Powers the "Unrealized gain / loss" summary tile and the detail view, only computed for cards where both this and estimatedValue are on record.
datePricedISO date (YYYY-MM-DD) this card was actually researched, not today's date by default
backlogBatchOptional label grouping cards priced in the same pass, e.g. "2026-08-08-full-backlog"

How to log a grading submission (cards sent off, not back yet)

A submission is a batch of cards currently at a grading company, before it has grades back. It is tracked separately from cards.json because it has no grade, cert number, or price of its own yet. Edit public/cgt/data/submissions.json by hand and add an object to the submissions array. Once a batch actually comes back, add the real graded cards to cards.json with their real cert numbers, and set this submission's status to "returned" with a real returnedDate rather than deleting the row, so there is still a record of how long that batch actually took.

Run node public/cgt/data/validate.js after every edit. It validates submissions.json the same way it validates cards.json: duplicate ids, a status outside the known list, a returnedDate that disagrees with status, and bad dates.

idUnique slug, e.g. "2026-08-psa-regular-batch-1"
descriptionPlain text describing what's in the batch, e.g. "12 cards, 2021 hockey rookies"
gradingCompanyPSA, BGS, SGC, CGC, HGA, or KSA
serviceLevelOptional, the paid tier as billed, e.g. "Regular", "Express", "Value Bulk"
cardCountOptional whole number, how many cards are in this batch
submittedDateISO date (YYYY-MM-DD) this batch was actually shipped out
trackingNumberOptional, the shipping tracking number for this batch
statusOne of: submitted, in-queue, grading, shipped-back, returned
returnedDateISO date this batch actually arrived back. Required once status is returned, otherwise leave null
notesFree-text notes
