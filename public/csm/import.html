Turn a research-spreadsheet CSV export into real rows for prospects.json

← CSM Pipeline
This page does not save anything by itself. Command Center's dashboards are static files with no database, so there is nothing here for this tool to write to directly. It parses a CSV, lets you map its columns to the real prospect schema, runs the exact same checks as node public/csm/data/validate.js, and then gives you a JSON file to download and use to replace public/csm/data/prospects.json by hand. Nothing is invented: a blank cell stays null, never a guess, and every imported row starts at the researched stage unless its own stage column says otherwise.
This never sends anything. Importing a batch only ever adds rows at the researched (or whatever real stage you log) part of the pipeline. There is no button anywhere on this page, or the board it feeds, that contacts a real person. A human still has to actually reach out and then log that touch for real afterward.

2. Paste or choose a CSV file

The first row must be a header row. Column names don't need to match the schema exactly, the next step lets you map each one, and any column you don't map is ignored. One row per prospect. There is no column for stageHistory, outreachLog, or contentIdeas; those are real, dated activity logs that only start once a prospect is actually in the pipeline, log them from the board itself as they really happen.

3. Map columns

Guessed automatically from the header names where possible. Check each one, especially contact channel type: whether this is a named decision-maker or a generic inbox is the single biggest driver of real reply rate on this board, worth getting right at import time.
